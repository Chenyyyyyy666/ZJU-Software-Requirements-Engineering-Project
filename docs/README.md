## 写作流程

1. **供稿**：各模块负责人按统一小标题写自己那部分，通过 Pull Request 提交，不直接改主干。
2. **合并**：主笔把各部分合并进主文档，统一术语、标题层级、图表编号和语气。
3. **定稿**：主笔检查页数限制、错别字、排版，并确认内容与实际实现一致。
4. **导出**：由主笔把 Markdown 转成 PDF，PDF 与源文件一并提交进仓库，保证"仓库里的版本就是交给老师的版本"。

## 交稿规则

- 每个里程碑截止前 **5 天**，各模块负责人把稿件提交到对应文件；逾期则由主笔按现有内容成文。
- 提交的 PDF 命名遵循课程要求：`PROJECT-MILESTONE[n]-[team_id]-[team_name]`。
- 篇幅限制：里程碑 1 的文档不超过 5 页；slides 不超过 10 页（slides 源文件放在 `../slides/`）。

## 相关约定

- 每份文档只由主笔维护最终版，其他人一律通过 Pull Request 供稿，避免出现多个互相冲突的版本。
- 会议纪要与过程材料不放这里，统一存放在 `../process/`。
- 本目录结构与文档版本由张崇洋维护；新增或调整文档前先在周会提出。
