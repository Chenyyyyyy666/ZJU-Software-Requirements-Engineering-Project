## 实现与设计

本模块读取 LoCoMo 原始对话，按白名单仅保留会话编号、轮次编号、说话人、会话时间和清洗后的文本，过滤图片链接，避免 QA 标准答案和 gold evidence 进入记忆构建。抽取按会话边界分块，每块最多 20 轮、12000 字符，通过 DeepSeek 的 JSON 输出接口生成结构化事实。

Memory 统一记录人物/实体、属性、值、事实描述、原始时间表达、事件时间及精度、来源轮次，并通过 memory_id、build_id 和输入哈希追踪版本。历史状态分别保存；无法确定到具体日期的时间允许为 null，不把会话时间直接当成事件发生时间。结构及引用经过 Pydantic 验证，JSON 采用原子写入。模型输出仍可能出现语义错误，结构验证不能代替证据核对。

检索提供 BM25、固定 revision 的本地 MiniLM 向量检索与 RRF 混合检索。候选结果包含原文引用与构建身份；显式实体/属性历史扩展与初始 Top-K 分开，便于推理模块检查历史，同时避免评测时把扩展结果混入初始检索指标。

## 验证与质量分析

四个 Bundle 保存/加载结果一致，145 个分块在禁止 API 调用的缓存重建中全部命中，完整 Bundle 与初次构建一致。2026-10-30 又在临时目录解压交付 ZIP，仅利用包内来源轮次和缓存完成相同比对，确认不依赖原始数据文件或原机器抽取缓存。运行环境的依赖版本与清单一致；验证平台为 Windows / Python 3.13.5，不能推定团队基准 Python 3.11 或 macOS 已验收。

58 项相关测试通过；四个对话各选首、中、末三条记忆内容，对三种检索方式执行共 36 组工程检查，命中原文均可回溯且重复结果一致。此检查不使用 QA 标签，也不是正式 Recall@K 评测。

Codex 对照原文核对 47 条定向样本，40 条未发现问题，7 条记录问题或限制：属性命名不一致导致历史链分散、可解析日期漏抽、把时间区间过度具体化，以及将模糊同行者补全成儿童。保留模型原始输出，未人工修饰数据掩盖错误。定向样本不能用于推断全量准确率，也不替代组员人工标注。详细样本和处理建议见 `milestone5-b-quality.md`。

## 局限与后续工作

实体别名和属性缺少统一归一化；相对时间解析在分块之间不稳定；模糊代词可能被过度解释。后续可通过通用属性规范、日期约束与证据一致性校验改善，并以版本化重建和独立评测比较效果。现有 7 项问题均已披露，未声明修复完成。QA F1、正式 Recall@K、状态更新准确率及三个方法的对照结果由 E/C 另行提供，不使用本模块的抽查比例替代。
