## 1 引言与术语

（供稿：陈易）

### 1.1 目的

本文规定"智能体动态记忆管理"系统在长程多会话问答场景下必须满足的功能需求、数据与接口需求、评测要求及非功能需求，作为里程碑 4 的设计、编码与测试依据，也是最终验收的依据。

### 1.2 范围

系统基于课程指定的 LoCoMo 长对话子集，覆盖以下环节：结构化记忆构建 → 有效记忆检索 → 动态状态解析与有效记忆选择 → 答案生成 → Web 端可视化 → 三指标评测与基线对照。

不包含：多模态（图片及图片描述）处理、跨对话记忆共享、模型训练与微调、面向公网的部署。

### 1.3 术语

| 术语 | 含义 |
| --- | --- |
| Memory | 从原始对话抽取的单条可验证事实，含内容、时间与来源轮次 |
| MemoryBundle | 一段对话的全部记忆与来源轮次的集合，含构建版本信息 |
| SourceTurn / SourceRef | 原始对话轮次 / 对轮次的引用，评测证据键为 `(conversation_id, session_id, turn_id)` |
| build_id | 一次构建的唯一版本标识，索引与实验记录必须与之匹配 |
| RETAIN | 两条记忆均有效，可同时成立 |
| UPDATE（SUPERSEDE） | 新记忆取代旧记忆，旧记忆不再是当前有效状态 |
| CONFLICT | 两条记忆不可同时成立且无充分依据消解 |
| 有效记忆 | 在当前问题与时间条件下仍然成立的记忆子集 |
| gold evidence | LoCoMo 为每道 QA 标注的证据轮次；仅用于评测，不得进入记忆构建或模型输入 |
| BM25 | 关键词检索打分函数，用于字面匹配召回 |
| RRF | Reciprocal Rank Fusion，按排名而非分数合并多路检索结果，本项目等权，`sum(1/(60+rank))` |
| Recall@K | 前 K 条检索结果是否覆盖该题至少一条关键证据 |
| QA F1 | 生成答案与标准答案的词级 F1 |

### 1.4 参考资料

《0 - Project (2026).pdf》第 9–12 页；`docs/proposal.md`；`docs/interfaces.md`；`docs/memory-design.md`；Maharana A, et al. *Evaluating Very Long-Term Conversational Memory of LLM Agents*. ACL 2024；`github.com/snap-research/locomo`。

## 2 总体描述与约束

### 2.1 产品定位

（供稿：于国庆）

智能体动态记忆管理系统面向长程多会话对话场景，解决普通向量 RAG 无法区分当前有效状态与过期历史状态的痛点。系统在答案生成前增加动态状态解析层，判定记忆间 RETAIN、UPDATE（SUPERSEDE）、CONFLICT 四类关系，筛选有效记忆，规避过期信息带来的错误回答；同时支持记忆、原始证据、状态演化可视化，并通过三项指标与基线方法对照，量化验证效果。

### 2.2 用户与使用场景

（供稿：许子萌）

【待补】至少覆盖三类场景：开发集调参、课堂演示、课程评测入口的无人值守运行。每类场景写明使用者与目标。

## 5 评测与验收要求

（供稿：陈易）

### 5.1 数据划分与隔离

| 项 | 规定 |
| --- | --- |
| 数据来源 | 课程从官方发布的 10 段 LoCoMo 长对话中选定 6 段：4 段开发集、2 段独立测试集，其余 4 段可作为扩展评测；具体编号以课程通知为准 |
| 开发集用途 | 用于提示词、检索参数与 K 值调试 |
| 测试集用途 | 仅在方案冻结后运行，用于最终评测；不得用于调参 |
| 隔离规则 | QA 问题文本、标准答案、gold evidence、标注事件摘要与问题类型标签，均不得进入记忆构建、检索索引或任何送给模型的输入 |
| 允许的输入 | 仅原始对话文本（含说话人、会话时间、原始轮次 ID） |
| 通用性规则 | 禁止针对具体题目写死答案或按关键词匹配做定向处理；所有规则必须对未见过的对话同样成立 |
| gold evidence 用途 | 仅用于评测阶段计算 Recall@K 与错误归因 |

### 5.2 评测指标

| 编号 | 指标 | 定义与口径 |
| --- | --- | --- |
| M-1 | 问题回答 F1 | 使用 LoCoMo 官方评测脚本，对生成答案与标准答案做词级 F1；每题输出一条答案，汇总开发集与测试集的平均值 |
| M-2 | 证据记忆检索 Recall@K | 将标注的 gold evidence 对齐到记忆的来源轮次；前 K 条检索结果覆盖该题至少一条关键证据即该题命中。正式报告 `Recall@1` 与 `Recall@5`，并记录不同 K 下的变化 |
| M-3 | 动态状态更新判断准确率 | RETAIN / UPDATE（SUPERSEDE）/ CONFLICT 判定的正确比例；报告总体准确率，并按类别统计混淆情况 |

三项指标分别对应链路的三段：检索段用 M-2 单独监控，解析段用 M-3，生成段用 M-1，便于定位错误环节。

### 5.3 对照方法

| 方法 | 定义 | 说明 |
| --- | --- | --- |
| Full Text | 不做检索与状态解析，完整对话直接交给模型 | 记录平均 token 以体现其成本 |
| Vector RAG | 仅按向量相似度取 Top-K 后直接生成答案 | 不做状态关系判断 |
| 本组方法 | 多路检索 → 状态解析过滤 → 生成答案 | 即第 3 节全部功能需求 |

M-3 对两个基线标记为"不适用"，因为它们不含状态解析环节。

### 5.4 课程评测接口

数据文件 `locomo.json` 位于仓库根目录。评测入口为参数化命令行脚本：

```text
python [评测入口] --conversation [conv_id] --questions [questions.json] --output answers.json
```

输出要求：每题一句话答案，标明题号；系统内部的记忆结构不要求统一格式。正式格式以助教通知为准，入口脚本保持参数化以便适配。

### 5.5 结果记录与可复现

1. 三项指标与平均 token 同表汇总，按方法分行；开发集与测试集结果分别记录。
2. 实验的配置、日志与错误案例一并保留，记录在 `experiments/`。
3. 相同输入与配置下重复运行结果可复现；模型响应经缓存复用，避免重复调用与重复计费。
4. 任一指标无法计算，视为对应功能需求未完成。
