# 软件需求规格说明书

## 1. 引言

### 1.1 目的

本文规定“智能体动态记忆管理”系统在长程、多会话问答场景中必须满足的功能需求、外部接口需求、非功能需求和评测要求。本文用于指导里程碑 4 的设计、编码与测试，并作为最终验收依据。

### 1.2 文档约定

- “必须”表示验收前必须满足；“应”表示预期满足且需说明偏差；“可”表示可选能力。
- 本文件不重复定义数据结构与函数签名；字段、默认值和异常类型以 [`interfaces.md`](interfaces.md) 为准。
- 需求编号用于交叉引用和追踪：`FE` 为系统功能，`FR` 为功能需求，`NFR` 为非功能需求，`C` 为约束，`A` 为假设或依赖，`M` 为评测指标。
- 优先级采用“必须、应该、可选”三级。无特别说明时，第 3 章中的功能需求均为“必须”。

### 1.3 预期读者与阅读建议

| 读者 | 主要关注章节 | 阅读建议 |
| --- | --- | --- |
| 课程教师与助教 | 1、3、4、5、6 | 从范围、功能需求、外部接口和验收标准判断交付完整性 |

### 1.4 项目范围

系统基于课程指定的 LoCoMo 长对话子集，覆盖“结构化记忆构建 → 有效记忆检索 → 动态状态解析与有效记忆选择 → 答案生成 → Web 可视化 → 三指标评测与基线对照”的完整链路。

系统目标是保留历史事实，并在回答当前问题时区分有效状态与已更新状态。范围外内容包括：多模态数据、跨对话记忆共享、模型训练或微调、面向公网的部署，以及物理设备控制。

## 2. 总体描述

### 2.1 产品视角

本系统是面向课程数据的一体化记忆问答应用，不是通用聊天机器人。系统每次处理一段独立对话，通过版本化 `MemoryBundle` 连接离线记忆构建、在线检索与推理、Web 展示和课程评测。

```text
locomo.json
    → SourceTurn / MemoryBundle
    → RetrievalResult
    → MemoryRelation / AnswerRecord
    → Web 页面或课程评测 answers.json
```

系统依赖课程数据、DeepSeek 官方接口和本地 MiniLM 模型；内部模块的数据契约由 `interfaces.md` 规定。

### 2.2 产品功能概览

| 编号 | 功能 | 优先级 | 交付价值 |
| --- | --- | --- | --- |
| FE-01 | 结构化记忆构建与存储 | 必须 | 将原始对话转换为可追溯、带版本的原子事实 |
| FE-02 | 有效记忆候选检索 | 必须 | 通过关键词、向量及混合召回缩小状态判定范围 |
| FE-03 | 动态状态解析与答案生成 | 必须 | 判定 RETAIN、UPDATE、SUPERSEDE、CONFLICT，并依据有效记忆作答 |
| FE-04 | Web 记忆与状态可视化 | 必须 | 展示记忆、原始证据和状态演化，支持人工核验与课堂演示 |
| FE-05 | 评测与课程接口 | 必须 | 生成课程要求的答案文件，计算三项指标并完成基线对照 |

### 2.3 用户类别与特征

| 用户类别 | 特征与需求 |

| 后续维护者 | 需要依赖清晰的数据契约、构建版本和可重复的命令，以定位和修改模块 |

## 3. 系统功能

### 3.1 结构化记忆构建与存储

#### 3.1.1 描述与优先级

将课程对话中的文本、说话人、会话时间、轮次来源以及人物、事件、时间和状态事实转换为有来源、可持久化的原子 Memory。该功能是全部在线功能的输入基础，优先级为“必须”。逐轮 `turns` 模式只用于基线和离线联调，不能替代真实语义抽取。

#### 3.1.2 刺激—响应序列

- 输入 `sample_id`：系统读取对应对话并返回清洗后的 SourceTurn 列表。
- 发起记忆构建：系统按会话分块抽取事实，保留新旧事实，输出 Memory 和 `build_id`。
- 请求保存：系统校验 schema、唯一 ID 和来源一致性，原子写入 UTF-8 JSON；校验失败时拒绝覆盖原文件。

#### 3.1.3 功能需求

| 编号 | 需求 | 输入 / 处理 / 输出 / 异常 | 验收依据 | 实现位置 |
| --- | --- | --- | --- | --- |
| FR-01 | 按对话读取和清洗原始文本 | 输入：LoCoMo 文件、`sample_id`；处理：按会话及轮次原序读取，移除图片链接和纯图片轮次，仅保留原文、说话人、时间和轮次 ID；输出：SourceTurn 列表；异常：文件缺失、未知或重复对话、轮次 ID 错误时明确报错，未知时间保留 `null` 并警告 | 改写 QA、答案和标注摘要后构建结果不变；清洗后无图片链接；不同对话来源不混用；合法空对话返回空列表 | `src/memory/locomo.py` |
| FR-02 | 抽取人物、事件、时间和状态事实 | 输入：FR-01 的原始轮次；处理：按会话分块调用 DeepSeek，保留新旧事实，用会话日期辅助解析相对时间；输出：有原始来源的原子 Memory，未知字段留空；异常：越界来源、非法 JSON、截断输出有界重试，失败时不导出伪成功结果 | Mock 验证字段、来源、重试与缓存；真实单段对话核对人物、事件、状态、时间和原文支持性；记录样本与误差，不用 Mock 代替真实质量验证 | `src/memory/build.py`、`extract.py` |
| FR-03 | 持久化可追溯、带版本的记忆 | 输入：合法 MemoryBundle；处理：校验 schema、唯一 ID、来源和时间一致性，原子写入 UTF-8 JSON；输出：可重新加载的完整 bundle 及 `build_id`；异常：不兼容 schema、重复 ID、缺失或跨对话来源拒绝保存，并保留原文件 | 保存后加载对象一致；同输入、配置和缓存结果产生相同 `build_id` 与 Memory ID；输入或结果变化时版本改变；索引拒绝混用不同 bundle | `src/common/models.py`、`json_io.py`、`src/memory/store.py` |

### 3.2 有效记忆候选检索

#### 3.2.1 描述与优先级

从指定对话的 MemoryBundle 中产生供后续状态解析使用的候选记忆。检索先限定对话，并在截取候选前应用显式过滤条件；不得因为问题包含“当前”就提前删除旧事实。优先级为“必须”。

#### 3.2.2 刺激—响应序列

- 关键词查询：系统执行 BM25 排名并返回不超过 K 条带分数的 Memory 命中。
- 语义或混合查询：系统执行向量检索或 BM25 + 向量 RRF 融合，去重后返回 Top-K 和 trace。
- 证据或历史请求：系统按来源读取原始轮次或关联历史，返回与初始 Top-K 分离的结果。

#### 3.2.3 功能需求

| 编号 | 需求 | 输入 / 处理 / 输出 / 异常 | 验收依据 | 实现位置 |
| --- | --- | --- | --- | --- |
| FR-04 | 关键词候选检索 | 输入：索引、对话 ID、问题、K 和可选过滤；处理：BM25 排名；输出：不超过 K 条有序命中，带分数、Memory 和构建身份；异常：空问题、非法 K、跨对话请求报错；无词项交集返回空命中 | 来源已知的合成查询命中目标轮次；重复查询排序一致；过滤先于截取；`top_k` 为正整数且不大于 `candidate_k` | `src/index/bm25.py` |
| FR-05 | 语义候选检索 | 输入同 FR-04；处理：固定版本 MiniLM 编码、余弦相似度排名、复用带构建与模型身份的缓存；输出：有序 Top-K 及模型和通道信息；异常：模型缺失、超 token 上限、缓存损坏或维度非法时明确报错 | 真实模型本地运行且来源可回溯；缓存重载与首次结果一致；身份变化不复用旧缓存；模型测试与真实运行分别记录 | `src/index/embeddings.py`、`bm25.py` |
| FR-06 | 混合召回与去重 | 输入同 FR-04，模式为 `hybrid`；处理：两路各取 `candidate_k`，按 Memory ID 去重并用等权 RRF 合并；输出：最终 Top-K、各路分数与排名、trace；异常：任一路失败即报错，不伪装成成功融合 | 同一 Memory 最多出现一次；按融合分降序、同分按 ID 排序；分数均为有限值；结果可追溯到各路候选 | `src/index/bm25.py` |
| FR-07 | 证据回溯与关联历史读取 | 输入：当前 bundle 与 Memory ID 或来源引用，或实体、属性及排除 ID；处理：读取原轮次或按原文顺序取关联历史；输出：去重来源、历史列表及 `truncated` 标记；异常：来源或记忆不存在、`limit` 非法时报错 | 每条候选均可回溯原文；旧状态保留；历史结果与初始 hits 分开；返回对象被修改不污染存储 | `src/memory/store.py`、`src/index/context.py` |

### 3.3 动态状态解析与答案生成

#### 3.3.1 描述与优先级

系统根据问题分析结果，对同一实体和属性的候选记忆判断时效关系，形成当前有效记忆集合并生成可追溯答案。该功能是关键路径，优先级为“必须”。

#### 3.3.2 刺激—响应序列

- 接收问题：系统抽取实体、时间范围、时间表达、属性和置信度。
- 接收候选 Memory：系统按实体和属性分组，判定 RETAIN、UPDATE、SUPERSEDE 或 CONFLICT。
- 接收有效关系和候选记忆：系统组装版本化 prompt，调用 DeepSeek 生成一句话答案和 AnswerRecord。
- 构建版本不匹配：系统抛出 `RuntimeError` 并要求重建索引，不返回跨 bundle 结果。

#### 3.3.3 功能需求

| 编号 | 需求 | 输入 / 处理 / 输出 / 异常 | 验收依据 | 实现位置 |
| --- | --- | --- | --- | --- |
| FR-08 | 从问题中抽取状态判定关键要素 | 输入：问题文本、`conversation_id`；处理：调用 DeepSeek 官方接口并关闭 thinking，抽取 `entity`、`time_scope`、`time_expression`、`attribute`、`confidence`；输出：符合 `interfaces.md` 契约的 JSON；异常：非法 JSON 重试 2 次，仍失败则记录日志并中断该题，不输出假成功 | 开发集问题 `attribute` 非空率和 JSON 可解析率均为 100%；`time_scope` 抽样人工核对准确率不低于 80%；字段与 `interfaces.md` 一致 | `src/reasoning/query_analyzer.py` |
| FR-09 | 判定候选记忆的时效关系 | 输入：候选 Memory，含内容、实体、属性、时间和来源；处理：仅比较相同 `(entity, attribute)` 组，综合时间和上下文判定；双方时间均缺失时判为 CONFLICT，跨组直接视为 RETAIN；输出：MemoryRelation 列表及 reason、sources；异常：非法 JSON 重试 2 次，仍失败降级为 CONFLICT 并记录日志 | 输出 100% 符合 schema；开发集总体判定准确率不低于 70%，并报告四类混淆矩阵；时间缺失样本 100% 判为 CONFLICT；跨组记忆不触发模型调用；相同输入与 prompt 版本结果一致 | `src/reasoning/relation_judge.py` |
| FR-10 | 选择有效记忆并生成答案 | 输入：MemoryRelation、Query 分析结果和候选 Memory；处理：RETAIN 全保留，UPDATE 合并，SUPERSEDE 只保留新值，CONFLICT 双留并标记；调用版本化 prompt 生成答案；输出：含 `question_id`、`answer`、`valid_memory_ids`、`conflict`、`build_id` 的 AnswerRecord；异常：生成失败重试 2 次，仍失败输出空答案并记录日志，不中断批量评测 | SUPERSEDE 场景旧值 100% 不进入答案生成；冲突样本抽检 100% 包含冲突说明；引用记忆均可回溯原始轮次；答案符合课程接口；记录每题 token 消耗 | `src/reasoning/memory_selector.py`、`answer_generator.py` |
| FR-11 | 保证状态解析与答案可追溯 | 输入：AnswerRecord 与 MemoryRelation；处理：携带 `build_id` 和被引用 Memory ID，证据键统一为 `(conversation_id, session_id, turn_id)`；输出：可供评测和前端消费的结构化结果；异常：引用 `build_id` 与当前 bundle 不一致时抛出 `RuntimeError` | 每条答案和关系均含 `build_id`；有效记忆与来源均可定位，定位失败率为 0；Recall@K 证据对齐使用同一口径 | `src/reasoning/` |

### 3.4 网页记忆与状态可视化

#### 3.4.1 描述与优先级

Web 界面用于浏览和解释系统结果，调用现有 Memory、来源读取、检索和推理模块，不在前端重新推断状态关系。该功能用于人工核验和课堂演示，优先级为“必须”。

#### 3.4.2 刺激—响应序列

- 选择对话：系统显示该构建下的 Memory 列表、筛选结果和 `build_id`。
- 打开记忆：系统显示 Memory 详情及其原始证据轮次。
- 提交问题：系统显示答案、被引用 Memory 和可用证据入口，不保留上一题状态。
- 查看关系：系统按方向显示四类关系，并可跳转到证据详情。

#### 3.4.3 功能需求

| 编号 | 需求 | 输入 / 处理 / 输出 / 异常 | 验收依据 | 实现位置 |
| --- | --- | --- | --- | --- |
| FR-12 | 按对话浏览结构化记忆 | 输入：`conversation_id` 与可选分页或筛选条件；处理：读取当前 MemoryBundle，按稳定顺序展示内容、实体、属性、时间和来源数量；输出：记忆列表及 `build_id`，空对话显示空状态；异常：未知对话、非法分页参数或 bundle 不可读时返回明确错误，不展示其他对话或旧构建内容 | 多记忆样例的列表、顺序、`build_id` 和筛选结果正确；空 bundle 显示空状态；非法参数有提示；不出现跨对话记忆 | `src/web/`（记忆浏览页与读取 API） |
| FR-13 | 从记忆详情回看原始证据 | 输入：`conversation_id`、`build_id`、`memory_id`；处理：通过 `sources` 读取 SourceTurn，按会话和轮次顺序展示说话人、时间及原文；输出：去重后的完整证据；异常：记忆不存在、版本不匹配或来源无法定位时明确报错，不生成替换文本 | 多来源样例中的轮次 ID、说话人和原文与 bundle 一致；重复来源只显示一次；错误引用不显示伪造文本 | `src/web/`（记忆详情与证据视图） |
| FR-14 | 在 Web 界面提交问题并查看依据 | 输入：`conversation_id`、当前 `build_id` 和非空问题；处理：调用检索、状态解析和答案生成，Web 层不改写判定；输出：答案、Memory ID、`build_id` 和证据入口；异常：空问题、未知对话、版本不匹配或后端失败时显示错误，不残留上一次答案 | 页面答案与 AnswerRecord 一致；切换对话或构建后不残留旧结果；错误可理解；Web 操作不改变命令行评测输出 | `src/web/`（问答页面与问答 API） |
| FR-15 | 可视化查询涉及的状态关系与演化 | 输入：MemoryRelation、相关 Memory 和来源；处理：按关系方向绘制节点，区分 RETAIN、UPDATE、SUPERSEDE、CONFLICT，并突出有效记忆；输出：关系视图、图例和空状态；异常：未知类型显示原始标签；引用缺失或版本不一致时不绘制错误连线 | 四种关系样例的标签、端点 ID、方向和证据跳转与输入一致；空关系及未知类型可显示；前端不自行增删关系 | `src/web/`（状态演化与关系可视化） |

### 3.5 评测与课程接口

#### 3.5.1 描述与优先级

系统提供参数化命令行入口，并计算问答质量、证据检索和状态更新判断三类指标。该功能是课程验收和最终对照分析的必要条件，优先级为“必须”。

#### 3.5.2 刺激—响应序列

- 评测脚本提交对话和问题参数：系统逐题运行并以固定题号写入 `answers.json`。
- 评测数据包含 gold evidence 和答案：系统仅用其计算指标，不将其送入构建或推理流程。
- 方案冻结后运行测试集：系统按同一配置运行本组方法和两个基线，输出可横向比较的结果。

#### 3.5.3 功能需求

## 附录 A：词汇表

| 术语 | 定义 |
| --- | --- |
| Memory | 从原始对话抽取的一条可验证事实，包含内容、时间与来源轮次 |
| MemoryBundle | 一段对话的全部记忆、来源和构建版本信息 |
| SourceTurn / SourceRef | 原始对话轮次 / 对轮次的引用；评测证据键为 `(conversation_id, session_id, turn_id)` |
| build_id | 一次记忆构建的唯一版本标识；索引、检索、推理和实验记录必须引用一致版本 |
| RETAIN | 两条记忆均有效，可以同时成立 |
| UPDATE / SUPERSEDE | 新记忆更新或替代旧记忆，旧记忆不再是当前有效状态 |
| CONFLICT | 两条记忆不能同时成立，且现有证据不足以消解冲突 |
| 有效记忆 | 在当前问题和时间条件下仍然成立的记忆子集 |
| gold evidence | LoCoMo 为 QA 标注的证据轮次；仅用于评测，不得进入构建或模型输入 |
| BM25 | 基于词项统计的关键词检索排序函数 |
| RRF | Reciprocal Rank Fusion，按排名合并多路检索结果；本项目等权，使用 `sum(1/(60+rank))` |
| Recall@K | 前 K 条检索结果是否覆盖该题的关键证据 |
| QA F1 | 生成答案与标准答案之间的词级 F1 分数 |

## 附录 B：分析模型

### B.1 端到端数据流

```text
原始对话 → 清洗 → 结构化 MemoryBundle
问题 → Query 分析 → BM25 / 向量 / hybrid 检索 → 候选 Memory
候选 Memory → 状态关系判定 → 有效 Memory → 答案生成
Memory + 证据 + 状态关系 → Web 展示
答案 + gold evidence → M-1 / M-2 / M-3 → 基线对照
```

### B.2 状态关系模型

| 关系 | 判定含义 | 对后续答案的影响 |
| --- | --- | --- |
| RETAIN | 两条记忆可同时成立 | 均作为有效记忆候选 |
| UPDATE | 新事实延续并更新同一状态 | 合并为当前有效状态，同时保留历史来源 |
| SUPERSEDE | 新事实替代旧状态 | 仅新值进入答案生成，旧值可追溯但不参与作答 |
| CONFLICT | 两条事实互斥且无法可靠消解 | 两条均保留并标记冲突，不得单方面隐去一条 |
