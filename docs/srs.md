## 1 引言与术语

（供稿：陈易）

### 1.1 目的

本文规定"智能体动态记忆管理"系统在长程多会话问答场景下必须满足的功能需求、数据与接口需求、评测要求及非功能需求，作为里程碑 4 的设计、编码与测试依据，也是最终验收的依据。

### 1.2 范围

系统基于课程指定的 LoCoMo 长对话子集，覆盖以下环节：结构化记忆构建 → 有效记忆检索 → 动态状态解析与有效记忆选择 → 答案生成 → Web 端可视化 → 三指标评测与基线对照。

不包含：多模态（图片及图片描述）处理、跨对话记忆共享、模型训练与微调、面向公网的部署。

### 1.3 术语

| 术语 | 含义 |
| --- | --- |
| Memory | 从原始对话抽取的单条可验证事实，含内容、时间与来源轮次 |
| MemoryBundle | 一段对话的全部记忆与来源轮次的集合，含构建版本信息 |
| SourceTurn / SourceRef | 原始对话轮次 / 对轮次的引用，评测证据键为 `(conversation_id, session_id, turn_id)` |
| build_id | 一次构建的唯一版本标识，索引与实验记录必须与之匹配 |
| RETAIN | 两条记忆均有效，可同时成立 |
| UPDATE（SUPERSEDE） | 新记忆取代旧记忆，旧记忆不再是当前有效状态 |
| CONFLICT | 两条记忆不可同时成立且无充分依据消解 |
| 有效记忆 | 在当前问题与时间条件下仍然成立的记忆子集 |
| gold evidence | LoCoMo 为每道 QA 标注的证据轮次；仅用于评测，不得进入记忆构建或模型输入 |
| BM25 | 关键词检索打分函数，用于字面匹配召回 |
| RRF | Reciprocal Rank Fusion，按排名而非分数合并多路检索结果，本项目等权，`sum(1/(60+rank))` |
| Recall@K | 前 K 条检索结果是否覆盖该题至少一条关键证据 |
| QA F1 | 生成答案与标准答案的词级 F1 |

### 1.4 参考资料

《0 - Project (2026).pdf》第 9–12 页；`docs/proposal.md`；`docs/interfaces.md`；`docs/memory-design.md`；Maharana A, et al. *Evaluating Very Long-Term Conversational Memory of LLM Agents*. ACL 2024；`github.com/snap-research/locomo`。

## 2 总体描述与约束

### 2.1 产品定位

（供稿：于国庆）

智能体动态记忆管理系统面向长程多会话对话场景，解决普通向量 RAG 无法区分当前有效状态与过期历史状态的痛点。系统在答案生成前增加动态状态解析层，判定记忆间 RETAIN、UPDATE（SUPERSEDE）、CONFLICT 四类关系，筛选有效记忆，规避过期信息带来的错误回答；同时支持记忆、原始证据、状态演化可视化，并通过三项指标与基线方法对照，量化验证效果。

### 2.2 用户与使用场景

（供稿：许子萌）

| 场景 | 使用者 | 目标与操作 |
| --- | --- | --- |
| 开发集检查与调试 | 项目开发成员 | 选择一段对话浏览结构化记忆，提交开发集问题，查看答案、候选/有效记忆及其原始证据；用状态关系视图定位检索或状态判断问题。该界面只展示当前构建与查询的结果，不修改 Memory 或 gold 标注。 |
| 课堂演示 | 项目成员、课程师生 | 选择包含状态变化的对话并提交“目前/后来”等问题，依次展示答案、被保留或更新的记忆关系和支持结论的原始轮次，说明动态状态解析的作用。 |
| 课程评测与无人值守运行 | 课程评测脚本/助教 | 通过命令行评测入口批量提交对话与问题并生成答案文件；此场景不依赖人工操作 Web 页面，Web 服务不可用不得阻断评测入口。 |

### 2.3 运行环境

（供稿：陈易）

| 项 | 要求 |
| --- | --- |
| 语言与运行时 | Python 3.11（见 `.python-version`） |
| 操作系统 | macOS 与 Windows 双平台必须可运行；统一使用 `pathlib` 处理路径，读写显式指定 `encoding="utf-8"` |
| 外部依赖 | DeepSeek 官方 API（不使用中转站，调用时关闭 thinking）；本地 MiniLM 向量模型固定 revision，无需 embedding API key |
| 网络 | 仅记忆抽取与答案生成需要联网；检索、存储与 Web 展示可离线运行 |

## 3 功能需求

### 3.1 记忆构建与存储

（供稿：鲁瑞特，2026-10-14）

结构化记忆必须保留历史事实，不能在构建时判定或删除“已过期”状态。`turns` 模式仅用于逐轮基线与离线联调，不能替代 FR-02 的真实语义抽取验收。字段、默认值与错误类型见 [interfaces.md](interfaces.md)。

| 编号 | 需求 | 输入 / 处理 / 输出 / 异常 | 验收依据 | 实现位置 |
| --- | --- | --- | --- | --- |
| FR-01 | 按对话读取和清洗原始文本 | 输入：LoCoMo 文件、sample_id；处理：按会话及轮次原序读取，移除图片链接和纯图片轮次，仅取原文、说话人、时间、轮次 ID；输出：SourceTurn 列表；异常：文件缺失、未知/重复对话或轮次 ID 明确报错，未知时间保留 null 并警告 | 改写 QA、答案和标注摘要后构建结果不变；清洗后无图片链接；不同对话来源不混用，合法空对话返回空列表 | `src/memory/locomo.py` |
| FR-02 | 抽取人物、事件、时间和状态事实 | 输入：FR-01 的原始轮次；处理：按会话分块调用 DeepSeek，保留新旧事实，用会话日期辅助解析相对时间；输出：有原始来源的原子 Memory，未知字段留空；异常：越界来源、非法 JSON、截断输出有界重试，失败不导出完整成功结果 | Mock 验证字段、来源、重试与缓存；真实单段对话另核对人物/事件/状态、可确定与不可确定时间及原文支持性；必须记录样本与误差，不能用 Mock 代替真实质量验证 | `src/memory/build.py`、`extract.py` |
| FR-03 | 持久化可追溯、带版本的记忆 | 输入：合法 MemoryBundle；处理：校验 schema、唯一 ID、来源和时间一致性，原子写入 UTF-8 JSON；输出：可重新加载的完整 bundle 及构建身份；异常：不兼容 schema、重复 ID、缺失/跨对话来源拒绝保存，保留原有文件 | 保存后加载对象一致；同输入、配置及缓存结果的 build_id/Memory ID 不变；输入或结果改变时构建版本改变；索引拒绝混用其他 bundle | `src/common/models.py`、`json_io.py`、`src/memory/store.py` |

### 3.2 有效记忆检索

（供稿：鲁瑞特，2026-10-14）

本节返回供状态解析使用的候选记忆；“对当前问题是否有效”由 3.3 节判断。所有检索先限定对话，并在截取候选前应用调用方显式给出的实体/属性条件。不得因问题包含“当前”就提前移除旧事实。

| 编号 | 需求 | 输入 / 处理 / 输出 / 异常 | 验收依据 | 实现位置 |
| --- | --- | --- | --- | --- |
| FR-04 | 关键词候选检索 | 输入：已建索引、对话 ID、问题、K 和可选过滤；处理：BM25 排名；输出：不超过 K 条有序命中，带分数、Memory 和构建身份；异常：空问题、非法 K、跨对话请求报错，无词项交集返回空命中 | 来源已知的合成查询命中目标轮次；重复查询排序一致；过滤先于截取，top_k 为正整数且不大于 candidate_k | `src/index/bm25.py` |
| FR-05 | 语义候选检索 | 输入：同 FR-04；处理：固定版本本地 MiniLM 编码、余弦相似度排名、复用带构建与模型身份的缓存；输出：有序 Top-K 及模型/通道信息；异常：缺失模型、超 token 上限、缓存损坏或维度非法明确报错 | 真实模型在本地运行，来源可回溯；缓存重载与首次结果一致，身份变化不复用旧缓存；模型测试与真实模型运行分开记录 | `src/index/embeddings.py`、`bm25.py` |
| FR-06 | 混合召回与去重 | 输入：同 FR-04，模式 hybrid；处理：两路各取 candidate_k，以 Memory ID 去重并用等权 RRF 合并；输出：最终 Top-K、各路原始分数/排名及 trace；异常：任一路失败则报错，不伪装成成功混合检索 | 同一 Memory 最多出现一次；按融合分降序、同分按 ID 排序；全部分数为有限值；结果能追溯到各路候选 | `src/index/bm25.py` |
| FR-07 | 证据回溯与关联历史读取 | 输入：当前 bundle 与 Memory ID/来源引用，或实体、属性及排除 ID；处理：读取原轮次或按原文顺序取关联历史；输出：去重来源、历史列表及 truncated 标记；异常：不存在的来源/记忆、非法 limit 报错 | 每条候选均可回溯原文；旧状态保留；历史结果与初始 hits 分开，不改变初始 Top-K；返回对象被修改不污染存储 | `src/memory/store.py`、`src/index/context.py` |

### 3.3 动态状态解析与答案生成

（供稿：于国庆）

| 编号  | 需求                                                         | 输入 / 处理 / 输出 / 异常                                    | 验收依据                                                     | 实现位置                                                   |
| :---- | :----------------------------------------------------------- | :----------------------------------------------------------- | :----------------------------------------------------------- | :--------------------------------------------------------- |
| FR-08 | 系统应能从用户问题中抽取影响状态判定的关键要素，输出结构化结果，作为候选记忆过滤与状态判定的约束 | **输入**：用户问题文本、当前 `conversation_id`。**处理**：调用 DeepSeek 官方接口（关闭 thinking），抽取 `entity`、`time_scope`、`time_expression`、`attribute` 与 `confidence`，字段名与 interfaces.md 契约保持一致。**输出**：JSON 对象，字段完整、可被下游解析。**异常**：返回非法 JSON 时重试 2 次，仍失败则记录日志并中断该题，不输出假成功结果 | 开发集问题上 `attribute` 非空率 100%，JSON 可解析率 100%；`time_scope` 抽样子集人工核对准确率 ≥ 80%（待开发集校准）；输出字段名与 docs/interfaces.md 一致 | `src/reasoning/query_analyzer.py`                          |
| FR-09 | 系统应对候选记忆按实体与属性分组后进行两两比较，判定 RETAIN / UPDATE / SUPERSEDE / CONFLICT 四类时效关系 | **输入**：检索返回的候选 Memory 列表（含 `content`、`entity`、`attribute`、`session_time`、`event_time`、`sources`）。**处理**：仅在 `(entity, attribute)` 相同的组内比较；综合时间顺序、实体一致性、属性一致性与事件上下文判定，不得仅依赖语义相似度；`event_time` 与 `session_time` 均缺失时强制判定 CONFLICT；跨 `(entity, attribute)` 组记忆直接视为 RETAIN，跳过 LLM 调用节约 token。**输出**：MemoryRelation 列表，每条含 `memory_a`、`memory_b`、`relation_type`、`reason`、`sources`（SourceRef 结构）。**异常**：非法 JSON 重试 2 次，仍失败则降级为 CONFLICT 并记录错误日志，不中断流水线 | 输出 100% 符合 MemoryRelation schema；开发集总体判定准确率 ≥ 70%（V2 阶段优化），并按四类报告混淆矩阵；时间缺失样本 100% 判为 CONFLICT；跨组记忆 100% 不触发模型调用；同输入同 prompt 版本下判定结果一致 | `src/reasoning/relation_judge.py`                          |
| FR-10 | 系统应根据状态关系判定结果选择当前有效记忆，组装 prompt 并调用 DeepSeek 生成答案 | **输入**：MemoryRelation 列表、Query 分析结果、候选 Memory 列表。**处理**：RETAIN 全部保留；UPDATE 合并为一条；SUPERSEDE 仅保留新值，旧值不送入 prompt；CONFLICT 双留并附加冲突标记。组装版本化答案 prompt，调用 DeepSeek 官方接口（关闭 thinking）生成一句话答案。**输出**：AnswerRecord，含 `question_id`、`answer`、`valid_memory_ids`、`conflict`、`build_id`。**异常**：生成失败重试 2 次，仍失败输出空答案并记录日志，不中断批量评测 | SUPERSEDE 场景下旧值 100% 不进入答案生成；冲突样本抽检 100% 包含冲突说明，不单方面选定结论；`valid_memory_ids` 均可通过 `get_memory` 与 `get_source_turns` 回溯原始轮次；答案格式 100% 符合课程评测接口；记录每题 token 消耗 | `src/reasoning/memory_selector.py` + `answer_generator.py` |
| FR-11 | 系统应保证状态解析与答案输出可追溯到具体构建版本与证据轮次   | **输入**：AnswerRecord 与 MemoryRelation。**处理**：输出携带 `build_id` 与被引用的 Memory ID；证据键统一为 `(conversation_id, session_id, turn_id)`。**输出**：结构化结果，可供评测脚本、前端消费。**异常**：引用的 `build_id` 与当前 MemoryBundle 不一致时抛出 RuntimeError，需重建索引后再解析 | 每条答案与关系记录均含 `build_id`；`valid_memory_ids` 与 `sources` 在当前 bundle 内均可定位，定位失败率为 0；Recall@K 证据对齐以此口径为准 | `src/reasoning/`                                           |

### 3.4 记忆与状态可视化

（供稿：许子萌）

Web 界面用于浏览和解释系统结果。它调用现有 Memory、来源读取、检索与推理模块，不在前端重新推断状态关系；HTTP 路由由 Web 模块定义，数据字段沿用 [interfaces.md](interfaces.md) 与 3.3 节定义的输出。

| 编号 | 需求 | 输入 / 处理 / 输出 / 异常 | 验收依据 | 实现位置 |
| --- | --- | --- | --- | --- |
| FR-12 | 按对话浏览结构化记忆 | **输入**：用户选择的 `conversation_id` 与可选分页/筛选条件。**处理**：读取该对话当前 MemoryBundle，按稳定顺序展示 Memory 的内容、实体、属性、时间及来源数量，并标明 `build_id`。**输出**：记忆列表及构建标识；空对话显示空状态。**异常**：未知对话、无效分页参数或 bundle 不可读取时返回明确错误状态，不展示其他对话或旧构建的记忆。 | 使用人工构造的多记忆 bundle 检查列表内容、顺序、build_id 与筛选结果；空 bundle 显示空状态；非法对话/参数有可理解的错误提示；不出现跨对话记忆 | `src/web/`（记忆浏览页与读取 API） |
| FR-13 | 从记忆详情回看原始证据 | **输入**：当前 `conversation_id`、`build_id` 与 `memory_id`。**处理**：通过 Memory 的 `sources` 读取对应 SourceTurn，按原始会话及轮次顺序展示说话人、时间和原文，并标示该 Memory 对应的来源。**输出**：记忆详情及可核对的原始证据；多来源时全部展示且去重。**异常**：记忆不存在、build_id 不匹配或来源无法定位时显示明确错误，不生成或替换证据文本。 | 对含多个来源的样例逐一核对页面中的会话/轮次 ID、说话人和原文与 bundle 一致；重复来源只显示一次；错误引用不显示伪造文本 | `src/web/`（记忆详情与证据视图） |
| FR-14 | 在 Web 界面提交问题并查看答案依据 | **输入**：`conversation_id`、当前 `build_id` 与非空问题文本。**处理**：调用检索及 3.3 节的状态解析/答案生成流程；Web 层不改写其判定结果。**输出**：答案、被引用的 Memory ID、构建标识及可用的证据入口。**异常**：空问题、未知对话、构建版本不匹配或后端处理失败时显示错误状态；不得把上一次请求的答案误显示为本次结果。 | 提交有效问题后显示与后端 AnswerRecord 一致的答案及引用；切换对话/构建后不残留旧结果；空问题和模拟后端错误均有提示；界面操作不改变命令行评测输出 | `src/web/`（问答页面与问答 API） |
| FR-15 | 可视化查询涉及的状态关系与演化 | **输入**：当前查询返回的 MemoryRelation、相关 Memory 和来源信息。**处理**：按关系类型呈现记忆节点及关系方向；分别标识 RETAIN、UPDATE、SUPERSEDE、CONFLICT，并突出答案所依据的有效记忆；节点可打开 FR-13 的证据详情。**输出**：可读的关系/演化视图及图例；空关系集合显示空状态。**异常**：未知关系类型以原始标签和通用样式展示；引用缺失或构建版本不一致时不绘制错误连线，并给出提示。 | 用覆盖四种关系的固定样例检查类型标签、端点 Memory ID、方向及证据跳转均与输入一致；空关系与未知类型可正常显示；视图不自行增删或重新判定关系 | `src/web/`（状态演化与关系可视化） |
| FR-16 | 用户可在 Web 界面导入 LoCoMo 格式的对话 JSON 并构建记忆 | **输入**：用户选择的 `.json` 文件；文件可以包含一个或多个 LoCoMo sample，包含多个时用户选择要构建的 `sample_id`。**处理**：后端校验 JSON、sample_id 与对话结构，调用现有记忆构建流程；只将原始对话轮次用于记忆抽取，不把 QA、gold evidence、observation 或摘要标注传入抽取器。构建成功后将 MemoryBundle 写入配置的记忆目录并更新可选对话列表。**输出**：构建状态、`conversation_id`、`build_id` 和 Memory 数量；成功后可立即浏览该 bundle。**异常**：无效 JSON、缺少/重复 sample_id、格式不支持、抽取配置缺失或构建失败时给出明确错误；失败不得留下可被页面当作完整结果加载的 bundle。 | 上传一个合法 LoCoMo sample 后可在对话列表中选择并查看记忆及来源；多 sample 文件可指定正确 sample_id；错误格式、未知/重复 sample_id 和构建失败均有错误提示且不产生完整 bundle；验证 QA、gold evidence、observation 与摘要字段不会进入抽取输入 | `src/web/`（上传页面/API，待实现）；复用 `src/memory/` |

## 5 评测与验收要求

（供稿：陈易）

### 5.1 数据划分与隔离

| 项 | 规定 |
| --- | --- |
| 数据来源 | 课程从官方发布的 10 段 LoCoMo 长对话中选定 6 段：4 段开发集、2 段独立测试集，其余 4 段可作为扩展评测；具体编号以课程通知为准 |
| 开发集用途 | 用于提示词、检索参数与 K 值调试 |
| 测试集用途 | 仅在方案冻结后运行，用于最终评测；不得用于调参 |
| 隔离规则 | QA 标注区不得进入记忆构建或检索索引；标准答案、gold evidence、标注事件摘要与问题类型标签不得进入任何送给模型的输入 |
| 允许的输入 | 离线构建仅使用原始对话文本（含说话人、会话时间、原始轮次 ID）；在线检索、查询分析和答案生成另接收当前待答问题，不读取其答案或其他标签 |
| 通用性规则 | 禁止针对具体题目写死答案或按关键词匹配做定向处理；所有规则必须对未见过的对话同样成立 |
| gold evidence 用途 | 仅用于评测阶段计算 Recall@K 与错误归因 |

### 5.2 评测指标

| 编号 | 指标 | 定义与口径 |
| --- | --- | --- |
| M-1 | 问题回答 F1 | 使用 LoCoMo 官方评测脚本，对生成答案与标准答案做词级 F1；每题输出一条答案，汇总开发集与测试集的平均值 |
| M-2 | 证据记忆检索 Recall@K | 将标注的 gold evidence 对齐到记忆的来源轮次；前 K 条检索结果覆盖该题至少一条关键证据即该题命中。正式报告 `Recall@1` 与 `Recall@5`，并记录不同 K 下的变化 |
| M-3 | 动态状态更新判断准确率 | RETAIN / UPDATE（SUPERSEDE）/ CONFLICT 判定的正确比例；报告总体准确率，并按类别统计混淆情况 |

三项指标分别对应链路的三段：检索段用 M-2 单独监控，解析段用 M-3，生成段用 M-1，便于定位错误环节。

### 5.3 对照方法

| 方法 | 定义 | 说明 |
| --- | --- | --- |
| Full Text | 不做检索与状态解析，完整对话直接交给模型 | 记录平均 token 以体现其成本 |
| Vector RAG | 仅按向量相似度取 Top-K 后直接生成答案 | 不做状态关系判断 |
| 本组方法 | 多路检索 → 状态解析过滤 → 生成答案 | 即第 3 节全部功能需求 |

M-3 对两个基线标记为"不适用"，因为它们不含状态解析环节。

### 5.4 课程评测接口

数据文件 `locomo.json` 位于仓库根目录。评测入口为参数化命令行脚本：

```text
python [评测入口] --conversation [conv_id] --questions [questions.json] --output answers.json
```

输出要求：每题一句话答案，标明题号；系统内部的记忆结构不要求统一格式。正式格式以助教通知为准，入口脚本保持参数化以便适配。

### 5.5 结果记录与可复现

1. 三项指标与平均 token 同表汇总，按方法分行；开发集与测试集结果分别记录。
2. 实验的配置、日志与错误案例一并保留，记录在 `experiments/`。
3. 相同输入与配置下重复运行结果可复现；模型响应经缓存复用，避免重复调用与重复计费。
4. 任一指标无法计算，视为对应功能需求未完成。
