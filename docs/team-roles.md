# 团队分工表（Team Roles and Responsibilities）

> 两条设计原则：
> 一是最重的工作流只承担核心工作，二是每一项辅助工作都有明确归属，
> 避免有人不知不觉背了两份职责。

## 一、角色分工表

| 角色 | 成员 | 核心职责 | 负责的文件与范围 | 不负责 |
| --- | --- | --- | --- | --- |
| 组长：项目管理与集成架构 | `陈易` | 里程碑计划与每周行动项追踪；主持周会；仓库设置、成员权限与分支保护；整体架构与模块接口的最终决策；代码脚手架搭建与各模块集成；对齐课程评测接口；部署与演示环境；最终提交邮件 | 仓库目录结构与骨架、`README.md`、`.editorconfig`、`.gitattributes`、`.pre-commit-config.yaml`、`process/` 周计划、集成入口脚本、提交材料 | 核心算法、文档技术章节、评测脚本 |
| 数据、记忆与检索基础设施 | `鲁瑞特` | 读取清洗 LoCoMo（过滤图片链接）；设计并冻结 Memory 结构；抽取人物、事件、时间、状态；统一 JSON 导出；建检索索引并提供检索接口（关键词/向量）；依赖与版本管理 | `src/memory/`、`src/index/`、`pyproject.toml`、`requirements.txt`、`.python-version`、Memory 结构说明、`docs/coding-standards.md` | 状态关系判定、prompt 调优、前端、评测脚本 |
| 动态状态解析（关键路径） | `于国庆` | Query 分析（类型、时间、实体）；判定记忆间的 RETAIN、UPDATE / SUPERSEDE、CONFLICT；选出当前有效记忆；设计与调优 prompt；通过 DeepSeek API 生成最终答案；第一阶段完成 DimMem 与 MRAgent 技术选型调研 | `src/reasoning/`、prompt 模板、答案生成逻辑、技术选型笔记 | 索引实现、测试脚本、图表、文档排版、可视化 |
| Web 应用与可视化 | `许子萌` | 后端接口与前端页面；结构化记忆与原始证据视图；状态演化与记忆关系可视化；演示脚本与展示素材截图 | `src/web/`、前端资源、演示素材 | Memory 结构、推理逻辑、评测脚本 |
| 评测与文档主笔 | `张崇洋` | 问答 F1、Recall@K、状态更新准确率的评测脚本；跑并记录 baseline 对照（Full Text、Vector RAG）；实验记录与图表；各里程碑文档的结构搭建、合并各人供稿与定稿、Markdown 转 PDF；slides 排版 | `src/eval/`、`experiments/`、`docs/`、`slides/`、`docs/git-conventions.md`（校对） | 核心算法、前端实现 |

## 二、辅助工作归属

这些工作最容易被顺手推给最忙的人，因此逐项指定归属。

| 辅助工作 | 归属 | 说明 |
| --- | --- | --- |
| Prompt 模板的版本整理与清理 | `张崇洋` | `于国庆` 写初版，`张崇洋` 维护版本并对比不同实验之间的差异 |
| 检索结果的单元测试 | `张崇洋` | `张崇洋` 写测试并反馈问题，`鲁瑞特` 或 `于国庆` 负责修 |
| Recall@K 与证据核对 | `张崇洋` | 依赖 `鲁瑞特` 提供的检索接口 |
| 批量实验跑批与结果图表 | `张崇洋` | 由 `于国庆` 决定需要对比哪些配置 |
| 状态关系的网页可视化 | `许子萌` | `于国庆` 只负责定义数据格式 |
| 记忆接口对齐（结构到推理） | `鲁瑞特` | `于国庆` 只消费接口，不修改结构 |
| 集成、部署与演示环境 | `陈易` | 包含根目录 `locomo.json` 的评测接口 |
| Slides 排版与 PDF 导出 | `张崇洋` | 内容由各模块负责人提供 |
| 仓库规则截图与过程材料归档 | `陈易` | 过程材料是交付物的一部分 |
| 跨平台环境统一（macOS 与 Windows） | `陈易` 负责，`鲁瑞特` 提供依赖清单 | 新成员从克隆到跑出第一条答案不超过 10 分钟 |

## 三、文档责任表

原则：内容谁懂谁写初稿，文档由一个人收口定稿。其他人的改动走 PR。

| 文档 | 主笔（定稿人） | 内容供稿 | 存放位置 |
| --- | --- | --- | --- |
| `README.md` | `陈易` | `鲁瑞特` 数据与记忆说明、`于国庆` 技术路线、`许子萌` 启动与部署步骤 | 仓库根目录 |
| 团队工作流文档（里程碑 1，不超过 5 页） | `张崇洋` | `陈易` 出计划、会议机制、仓库规范 | `docs/` |
| 分工表与时间计划表 | `陈易` | 全员各自确认自己的职责与投入 | 作为上表文档中的一节 |
| Proposal：目标范围与功能路线图（slides 不超过 10 页） | `陈易` 统筹 | `于国庆` 技术方案、`鲁瑞特` 数据方案、`许子萌` 架构图、`张崇洋` 排版定稿 | `slides/` |
| 需求规格说明书（里程碑 3） | `张崇洋` | `鲁瑞特` 数据与记忆需求、`于国庆` 检索与状态解析需求、`许子萌` 界面与可视化需求、`陈易` 约束与评测要求 | `docs/` |
| 中期设计与测试文档（里程碑 4） | `张崇洋` | 各模块负责人写自己部分，`许子萌` 出架构与流程图 | `docs/` |
| 最终报告（里程碑 5） | `张崇洋` | 全员按章节供稿 | `docs/` |
| 接口契约 `docs/interfaces.md` | 谁定义谁写，消费方确认 | `陈易` 汇总 | `docs/` |
| 代码规范 `docs/coding-standards.md` | `鲁瑞特` | `于国庆`、`许子萌`、`张崇洋` 确认 | `docs/` |
| Git 规范 `docs/git-conventions.md` | `陈易` | `张崇洋` 校对 | `docs/` |
| 会议纪要 | 每周轮值记录者 | 无需供稿 | `process/` |
| 周计划与行动项表 | `陈易` | 各成员更新自己的进度 | `process/` |
| 技术选型笔记（DimMem / MRAgent 调研） | `于国庆` | 无 | `docs/`，内部参考 |

约定：每个里程碑截止前 5 天，各模块负责人按固定小标题交稿到 `docs/` 对应文件；
逾期则由主笔按现有内容成文。

## 六、文件与目录归属

为避免两人同时修改同一文件，约定如下。

| 区域 | 只有这个人修改 |
| --- | --- |
| 仓库目录结构与骨架 | `陈易` |
| 整体架构与模块接口决策 | `陈易` 拍板，全员参与讨论 |
| Memory 结构与抽取 | `鲁瑞特` |
| 检索索引与接口 | `鲁瑞特` |
| 推理逻辑与 prompt | `于国庆` |
| 前端与 API 路由 | `许子萌` |
| 评测脚本与 `experiments/` | `张崇洋` |
| `docs/` 主文档 | `张崇洋`，其他人通过 PR 供稿 |
| 集成入口与仓库设置 | `陈易` |

约定：目录结构首次搭建后即冻结；新增、移动或重命名顶层目录需在周会提出，
由 `陈易` 执行，并同步更新 `README.md` 的 Repository Structure 一节。

## 七、会议与纪要轮值

从 9 月 28 日到 11 月 9 日共 **6 个项目周**。表中的周次按这个实际区间计算，
与课程日历上的教学周（Week 3 / 4 / 6 / 8）不是同一套编号。

| 项目周 | 日期区间 | 关键节点 | 组织者 | 纪要记录者 |
| --- | --- | --- | --- | --- |
| 第 1 周 | 9/28 - 10/4 | 建仓库、定分工、写里程碑 1 与 proposal 初稿 | `陈易` | `鲁瑞特` |
| 第 2 周 | 10/5 - 10/11 | 10/9 proposal 展示；10/10 交里程碑 1、2 | `陈易` | `于国庆` |
| 第 3 周 | 10/12 - 10/18 | 记忆构建与检索骨架跑通 | `陈易` | `许子萌` |
| 第 4 周 | 10/19 - 10/25 | 10/22-23 中期展示；10/24 交里程碑 3、4 | `陈易` | `张崇洋` |
| 第 5 周 | 10/26 - 11/1 | 功能冻结，跑对照实验 | `陈易` | `鲁瑞特` |
| 第 6 周 | 11/2 - 11/9 | 最终展示；11/9 交最终报告 | `陈易` | `于国庆` |

组织者固定，保证会议召开；纪要轮值，让过程工作平摊。

## 八、复盘与调整

- 每个里程碑结束时复盘本表，而不是只在开始前定一次。
- 记录交付了什么、什么延期了、由谁接手，并保持与 `README.md` 的 Team 表、
  `process/` 中的周计划一致。
- 若中期复盘时 `于国庆` 仍然过载，就把一个状态解析的子任务（例如 Query 类型分类）
  正式转给 `鲁瑞特`，并在文档中写明交接。
