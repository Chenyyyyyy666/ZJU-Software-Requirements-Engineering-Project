## 1 问题总览

本次评测一共 **7 条错误样本**：

1. 样本7：`gold=UPDATE`，`pred=RETAIN`
2. 样本12：`gold=SUPERSEDE`，`pred=RETAIN`
3. 样本14：`gold=UPDATE`，`pred=RETAIN`
4. 样本15：`gold=SUPERSEDE`，`pred=RETAIN`
5. 样本18：`gold=UPDATE`，`pred=RETAIN`
6. 样本19：`gold=CONFLICT`，`pred=UPDATE`
7. 样本23：`gold=CONFLICT`，`pred=UPDATE`

错误归类统计：

| 错误类型           | 数量 | 说明                                                     |
| ------------------ | ---- | -------------------------------------------------------- |
| UPDATE → RETAIN    | 3    | 模型保守，识别不出增量修正关系，判定为独立共存记忆       |
| SUPERSEDE → RETAIN | 2    | 无法识别旧事实被新事实彻底覆盖作废的替代关系，直接RETAIN |
| CONFLICT → UPDATE  | 2    | 将同一属性互斥的冲突错误识别为时序更新                   |

核心结论：模型依然偏向保守，优先输出 `RETAIN`；**SUPERSEDE 类别完全没有识别成功**；CONFLICT 有少量识别成功，但容易和 UPDATE 混淆。 和上一轮实验对比：Macro-F1 从 0.3039 提升至 0.4710，说明在类别区分能力上有改善；但整体准确率小幅下降（0.7619→0.7083），原因是RETAIN占比下降、非RETAIN测试样本占比变高，更能暴露模型短板。

## 2 各类错误分析

### 2.1 UPDATE → RETAIN（3例）

- 现象：真值为 `UPDATE`：同一实体、同一属性槽，新信息对旧信息做增量修正，旧信息不彻底失效，只是存在更新版本；模型认为两条记忆互不干扰，可以同时保留。
- 模型缺陷：对“微调、调整、修改计划”这类温和变更语义敏感度不足，只有特征非常明显的更新才能被识别。
- 区分边界：`UPDATE` ≠ `SUPERSEDE`；UPDATE 是**同一属性的新版本补充**，旧事实依然具备参考意义，没有被作废。
- 优化方向：强化实体+属性槽匹配逻辑；当实体和属性槽一致、取值不同，且没有“放弃、取消、废弃”等强作废词时，优先进入UPDATE判断分支。

### 2.2 SUPERSEDE → RETAIN（2例）

- 现象：真值为 `SUPERSEDE`：旧状态/旧计划彻底失效，被新状态完全顶替；模型无法捕捉“作废、替换、放弃”语义，把两条记忆当成独立事实保留。
- 模型缺陷：SUPERSEDE是当前模型最弱的类别，本轮2条SUPERSEDE全部漏检，没有一条被正确预测。
- 优化方向：增加强信号词特征：`give up / cancel / discard / replace / stop`；在prompt中重点强调SUPERSEDE定义：**旧事实不再成立、失去效力**。

### 2.3 CONFLICT → UPDATE（2例）

- 现象：真值为 `CONFLICT`：同一实体、同一属性，取值互斥，无法同时成立；模型默认是时序先后带来的信息迭代，判定为UPDATE。
- 模型缺陷：缺少时间一致性校验逻辑；无法区分「先后迭代更新」和「同一时间/同一决策下互斥」。
- 优化方向：增加时间槽校验：若两条记忆描述同一时刻、同一决策，属性取值相反，优先判定CONFLICT；时序上有先后、旧状态被替代，才走UPDATE/SUPERSEDE分支。

## 3 混淆矩阵与指标解读

1. **Accuracy 0.7083**：样本集RETAIN占比下降，指标更可信，不再依靠大量RETAIN拉高分数；
2. **Macro-F1 0.4710**：相比上一轮明显上涨，少数类（UPDATE、CONFLICT）的召回、精度得到改善；
3. 类别表现排序：`RETAIN > UPDATE > CONFLICT > SUPERSEDE`；SUPERSEDE是当前瓶颈，召回为0；
4. UPDATE 类别：3正3错，召回50%，还有很大提升空间；
5. CONFLICT 类别：1正2错，容易和UPDATE混淆。
