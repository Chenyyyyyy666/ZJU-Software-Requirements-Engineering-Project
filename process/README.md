# process 目录说明

本目录是**项目过程档案库**，存放"项目是怎么做出来的"的证据，而不是成果本身。

课程要求每个里程碑除了文档和 slides，还要提交一个 **Process files (ZIP)**，内容为线上会议截图、会议纪要、GitHub 仓库记录。同时，课程评分中的"版本控制"与"项目管理"两项也要靠这里的材料体现。**提交时间戳本身就是证据**，所以材料要当天入库，不要等截止前统一补。

## 目录结构

```text
process/
├── README.md                       # 本文件
├── templates/
│   └── meeting-minutes-template.md # 会议纪要模板（课程明确要求准备）
├── plan/
│   └── week-01-plan.md             # 每周计划与行动项
├── minutes/
│   └── 2026-09-28-week-01-minutes.md
└── snapshots/
    └── 2026-09-28-week-01-meeting.png
```

## 命名规则

文件名以日期开头，格式 `YYYY-MM-DD-<说明>`，按名称排序即为时间线：

- 会议纪要：`2026-09-28-week-01-minutes.md`
- 会议截图：`2026-09-28-week-01-meeting.png`
- 周计划：`week-01-plan.md`（按项目周编号）

## 更新时机与责任人

| 材料 | 更新时机 | 责任人 |
| --- | --- | --- |
| 周计划与行动项 | 每周例会前更新，会后补齐结论 | 陈易 |
| 会议纪要 | 会后当天 | 当周轮值记录者 |
| 线上会议截图 | 会议进行中 | 当周轮值记录者 |
| 模板与目录维护 | 按需 | 陈易 |
| 里程碑归档检查与打包 | 每个里程碑截止前 | 陈易 |

会议纪要轮值顺序（按项目周）：第 1 周 鲁瑞特 → 第 2 周 于国庆 → 第 3 周 许子萌 → 第 4 周 张崇洋 → 第 5 周 鲁瑞特 → 第 6 周 于国庆。

## 里程碑提交前检查

1. 本周的会议截图与纪要是否都已入库，且文件名规范。
2. 周计划中的行动项是否标注了负责人、截止时间与当前状态。
3. 是否有未记录的关键决策（例如接口调整、分工变更）。
4. 是否已剔除密钥、数据集和临时文件。
5. 打包为 ZIP 后，随文档和 slides 一起邮件提交。

## 不该放这里的内容

- API key 或任何密钥
- LoCoMo 数据集与大型原始文件
- 正式交付文档与 slides（分别在 `../docs/` 与 `../slides/`）
- 临时草稿与缓存文件
